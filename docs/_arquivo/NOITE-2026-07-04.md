## ⭐ PRINCÍPIO-GUIA DO EDITOR (Cássio, 2026-07-03)

> "O foco do projeto NÃO é o cliente ser profissional em montar um site — é
> montar o básico, com a cara do design da marca dele, pra estar na internet."

Consequência de design pro editor (fase de front "com primazia"):
- Peso quase todo no MODO SIMPLES: escolher cores/fontes da marca → editar
  texto (clique) → trocar imagem (arraste) → arrumar seções → publicar.
- Biblioteca de blocos = SEÇÕES prontas (Hero, Sobre, Serviços, Galeria,
  Depoimentos, Contato), NUNCA elementos crus (Div/Flex/Grid/Overflow).
- "Avançado" = só um "mais opções" discreto (espaçamento, uma cor pontual),
  NUNCA o painel Webflow (Positioning/Transforms/Filters/Backdrop).
- Os mockups (hambúrguer = simples; SlothUI/Figma = referência de posição das
  ferramentas) são só referência de LAYOUT; a alma é o princípio acima.
- Figma conectado (MCP): puxar `get_design_context` do componente exato na
  hora de construir e adaptar com NOSSOS tokens (Carta Náutica), sem importar
  código auto-gerado que briga com o DESIGN-NUCLEO.
- Isso é a "integração de janelas parte 2" também: manter a nav do painel
  visível dentro do editor (shell unificado), pro cliente nunca se perder.
